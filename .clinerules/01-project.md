
# Описание моего проекта

Я разрабатываю учебный проект YouTube Clone.
Это копия YouTube с основными функциями оригинального сервиса.

Я использую ИИ для написания кода, а сам отвечаю
за постановку задач, архитектуру и проверку результата.

## Для чего нужен проект

Пользователь должен иметь возможность:
- Зарегистрироваться и войти в аккаунт.
- Создать свой канал.
- Загружать видео.
- Просматривать видео.
- Ставить лайки и писать комментарии.
- Подписываться на каналы.
- Создавать плейлисты.
- Искать видео по названию.
- Загружать приватные видео и разрешать
  просмотр определённым пользователям.

Также должна быть система модерации:
- Пользователи могут отправлять жалобы.
- Модераторы могут скрывать видео.
- Администратор управляет ролями пользователей.

## Технологии

Backend:
- Python 3.13
- FastAPI
- SQLAlchemy 2.0
- PostgreSQL
- Alembic
- Pydantic

Хранение видео:
- MinIO или S3-совместимое хранилище.
- FFmpeg для обработки видео.

Инфраструктура:
- Docker
- Docker Compose
- Ubuntu

Тестирование:
- pytest
- httpx

Frontend:
- HTML
- CSS
- JavaScript

## Основные требования

1. Приложение должно запускаться через Docker Compose.
2. Должна быть документация Swagger по адресу /docs.
3. Видео должны храниться в объектном хранилище.
4. В базе данных должны храниться метаданные видео.
5. Доступ к приватным видео должен проверяться
   на backend.
6. Основные функции должны иметь автоматические тесты.
7. Нельзя хранить секреты непосредственно в коде.


## Пользовательский интерфейс (Frontend)

Я хочу сделать простой, но рабочий frontend для проекта.

Не нужно создавать сложное SPA-приложение
и использовать React, Vue или Angular.

Используй:
- Jinja2 для HTML-шаблонов.
- HTML5.
- CSS.
- JavaScript только там, где он действительно нужен.

FastAPI должен отдавать HTML-страницы через Jinja2 Templates.

## Необходимые страницы

1. Главная страница со списком доступных видео.
2. Страница просмотра видео с видеоплеером.
3. Страница регистрации.
4. Страница входа.
5. Страница загрузки видео.
6. Страница профиля пользователя или канала.
7. Страница модерации жалоб и управления видео.

Интерфейс должен поддерживать:
- Регистрацию и вход.
- Просмотр доступных видео.
- Загрузку видео.
- Отображение информации об авторе.
- Работу с приватными видео.
- Отображение ошибок и статусов операций.

## Требования к реализации

- Используй общие Jinja2-шаблоны и наследование шаблонов.
- Не дублируй HTML-код без необходимости.
- Разделяй HTML, CSS и JavaScript.
- Не размещай бизнес-логику в шаблонах.
- Проверяй права пользователя на backend.
- Не считай скрытие кнопок на frontend защитой доступа.
- Используй существующую серверную Cookie-аутентификацию.
- Предусмотри CSRF-защиту для форм и изменяющих состояние запросов.

Frontend должен быть простым и понятным.
Главная цель — продемонстрировать работу основных функций проекта,
а не создать коммерчески законченный видеохостинг.


## Как я хочу работать

Я хочу понимать,
как устроен написанный код.

Поэтому:
- Используй понятные названия переменных и функций.
- Не усложняй код без необходимости.
- Не создавай лишние абстракции.
- Объясняй сложные архитектурные решения.
- Не используй технологии, которых нет в проекте, без предварительного согласования.

Если требования неоднозначны, задай мне вопрос.
Не придумывай требования самостоятельно.

## Терминал
Терминал проекта использует git bash

При написании команд:

Не используй && и ||.

Для последовательного выполнения команд используй ; или отдельные вызовы.

Используй синтаксис git bash

Для Python используй виртуальное окружение проекта: venv\Scripts\python.exe.
