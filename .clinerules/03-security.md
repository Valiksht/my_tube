# Безопасность проекта

Я хочу, чтобы безопасность проекта была реализована правильно.
Не упрощай проверки ради того, чтобы код было легче написать.

## 1. Аутентификация

Для авторизации пользователей в браузере используй серверные сессии
с HttpOnly Cookie.

Не используй Bearer-токены в Authorization-заголовке
для аутентификации браузерного пользователя.

При входе пользователя:
- Проверь логин и пароль.
- Создай криптографически случайный идентификатор сессии.
- Сохрани сессию в PostgreSQL.
- Установи Cookie с идентификатором сессии.
- Не храни в Cookie пароль или другие персональные данные.
- Предпочтительно храни в БД хеш идентификатора сессии,
  а не его исходное значение.

Cookie должна иметь настройки:
- HttpOnly=True.
- Secure=True в production.
- SameSite=Lax (если архитектура приложения позволяет).
- Path=/.
- Ограниченный срок действия.

При каждом защищённом запросе:
- Получи идентификатор сессии из Cookie.
- Найди сессию в БД.
- Проверь срок действия и статус сессии.
- Получи пользователя, связанного с сессией.
- Проверь его права доступа.

При выходе пользователя:
- Отзови или удали сессию в БД.
- Очисти Cookie в браузере.

Предусмотри возможность отозвать все сессии пользователя.

## 2. CSRF-защита

Так как браузер автоматически отправляет Cookie,
предусмотри защиту от CSRF.

Для запросов, изменяющих состояние приложения,
используй подходящий механизм CSRF-защиты.

Не считай SameSite единственной защитой.

## 3. Пароли

- Никогда не храни пароли в открытом виде.
- Используй надёжный алгоритм хеширования паролей.
- Проверяй пароль через функцию проверки хеша.
- Не возвращай хеш пароля в API-ответах.

## 4. Роли и права

В проекте должны быть роли:
- user — обычный пользователь.
- moderator — модератор.
- admin — администратор.

Не ограничивайся скрытием кнопок на frontend.
Проверяй права на backend при каждом защищённом действии.

## 5. Приватные видео

- Приватное видео может смотреть только владелец
  и пользователи, которым явно разрешён доступ.
- Проверяй права до начала передачи файла.
- Не выдавай прямую публичную ссылку на приватное видео.
- Не допускай обхода проверки через изменение URL.

## 6. Загрузка файлов

- Проверяй размер загружаемого файла.
- Проверяй допустимые форматы.
- Не доверяй имени и MIME-типу, переданным клиентом.
- Не используй имя загруженного файла как путь хранения.
- Генерируй собственные уникальные имена объектов.
- Не сохраняй загруженные видео в публичную директорию frontend.

## 7. Секреты и настройки

- Не записывай пароли, ключи и секреты в исходный код.
- Используй .env для локальной конфигурации.
- Добавь .env в .gitignore.
- Создай .env.example без настоящих секретов.
- Не выводи секреты в логах.

## 8. Правила разработки

Если изменение затрагивает безопасность:
- Сначала объясни, какие риски оно затрагивает.
- Предложи план реализации.
- Не отключай проверки ради прохождения тестов.
- Добавляй тесты на успешные и запрещённые действия.
- Не меняй механизм аутентификации без согласования со мной.
