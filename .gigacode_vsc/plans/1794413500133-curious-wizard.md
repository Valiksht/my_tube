# Отчёт: Настройки Alembic — проблемы и план исправления

## Найдено 2 критических и 2 незначительных проблемы

---

### Критическая проблема #1: Пустой metadata в env.py

**Файл:** `alembic/env.py`, строка 5

```python
from app.models.base import metadata
```

**Проблема:** Импорт идёт только из `base.py`, который создаёт пустой `metadata = Base.metadata`. Метаданные заполняются таблицами только когда модели (User, Video, Channel и т.д.) импортируются и регистрируются через DeclarativeBase. Поскольку `base.py` не импортирует другие модели, а `env.py` не импортирует `app.models`, объект `metadata` пустой.

**Последствия:**
- `alembic revision --autogenerate` не увидит существующие модели и будет генерировать миграцию создания всех таблиц заново
- `alembic upgrade head` может работать (читает файл миграции напрямую), но автогенерация сломана
- При сравнении БД с кодом Alembic не сможет обнаружить изменения в схемах

**Исправление:** Добавить импорт всех моделей в `env.py` перед использованием metadata.

---

### Критическая проблема #2: Жёстко заданный URL базы данных в alembic.ini

**Файл:** `alembic.ini`, строка 9

```ini
sqlalchemy.url = postgresql+asyncpg://postgres:postgres@localhost:5432/mytube_db
```

**Проблема:** URL указывает на `localhost`. Это работает при локальном запуске, но НЕ работает внутри Docker Compose, где база данных доступна по имени сервиса `postgres`.

**Последствия:**
- Миграции не применяются при запуске через Docker Compose
- API контейнер не подключается к БД из-за неверного хоста

**Исправление:** Использовать переменные окружения для подстановки хоста, порта и учётных данных.

---

### Незначительная проблема #3: Неполный downgrade в миграции

**Файл:** `alembic/versions/8817bb8f02d3_initial_schema.py`, строки 185–195

```python
def downgrade() -> None:
    op.drop_table('hidden_content')
    op.drop_table('reports')
    ...
    op.drop_table('users')
```

**Проблема:** `downgrade()` удаляет таблицы, но не индексы. В `upgrade()` создаются индексы (`ix_users_id`, `ix_videos_channel_id` и т.д.), которые не удаляются в `downgrade()`.

**Последствия:** При `alembic downgrade` индексы останутся в БД, что может вызвать ошибки при повторном применении миграции.

**Исправление:** Добавить `op.drop_index()` для всех созданных индексов.

---

### Незначительная проблема #4: Dockerfile.production не запускает миграции

**Файл:** `Dockerfile.production`, строка 57

```dockerfile
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000", "--workers", "4"]
```

**Проблема:** Контейнер API сразу запускает uvicorn без применения миграций. Если БД пуста, приложение упадёт с ошибкой при первом запросе к БД.

**Последствия:**
- Приложение не запускается на чистой БД
- Нет автоматического применения миграций при старте

**Исправление:** Добавить запуск `alembic upgrade head` перед стартом uvicorn (в entrypoint-скрипте или как команду в docker-compose).

## План исправления

### Шаг 1: Исправить env.py — добавить импорт моделей

В `alembic/env.py` добавить импорт всех моделей перед использованием metadata:

```python
# Import all models to populate metadata
import app.models.users      # noqa: F401
import app.models.channel    # noqa: F401
import app.models.video      # noqa: F401
import app.models.like       # noqa: F401
import app.models.comment    # noqa: F401
import app.models.subscription  # noqa: F401
import app.models.session    # noqa: F401
import app.models.moderation # noqa: F401
```

### Шаг 2: Сделать URL базы данных настраиваемым

В `alembic.ini` заменить жёсткий URL на переменную:

```ini
sqlalchemy.url = ${sqlalchemy.url:postgresql+asyncpg://postgres:postgres@localhost:5432/mytube_db}
```

Или лучше — читать URL из переменных окружения прямо в `env.py` (более гибко):

```python
import os

def run_migrations_online() -> None:
    database_url = os.getenv("DATABASE_URL") or config.get_main_option("sqlalchemy.url")
    ...
```

### Шаг 3: Добавить drop_index в downgrade

Добавить удаление всех индексов в `downgrade()` перед `drop_table`.

### Шаг 4: Добавить запуск миграций в Docker

Создать `scripts/docker-entrypoint.sh` или добавить команду в `docker-compose.production.yaml` для сервиса `api`:

```yaml
command: >
  bash -c "
    alembic upgrade head &&
    uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 4
  "
```

## Порядок выполнения

1. Шаг 1 (env.py) — обязательно, ломает автогенерацию
2. Шаг 2 (URL) — обязательно для Docker
3. Шаг 3 (downgrade) — желательно для корректного отката
4. Шаг 4 (entrypoint) — желательно для удобства
