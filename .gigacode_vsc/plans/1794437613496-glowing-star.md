# Fix CSRF token validation on POST requests

## Проблема

При регистрации (`POST /register`) возникает ошибка:
```json
{"detail":"CSRF token missing or invalid"}
```

## Причина

В middleware `add_csrf_token` (`app/main.py`, строки 72–96) на **каждый** запрос вызывается `generate_csrf_token()`, и токен записывается в `request.state.csrf_token`:

```python
@app.middleware("http")
async def add_csrf_token(request: Request, call_next):
    csrf_token = None
    if request.method == "GET":
        csrf_token = generate_csrf_token()      # ← генерация для GET
        request.state.csrf_token = csrf_token
    
    response = await call_next(request)
    
    # Cookie устанавливается только для GET — это правильно
    if request.method == "GET" and csrf_token:
        response.set_cookie(...)
    
    return response
```

Хотя cookie устанавливается только для GET, проблема в том, что **на POST-запросе middleware всё равно вызывает `generate_csrf_token()` и перезаписывает `request.state.csrf_token`**. Это не влияет напрямую на валидацию (она читает cookie и form напрямую), но создаёт риск рассинхронизации.

**Основная проблема**: `verify_csrf_token` (`app/core/csrf.py`) проверяет только два паттерна:
1. Cookie vs заголовок `X-CSRF-Token`
2. Cookie vs поле формы `csrf_token`

Но **не проверяет**, что cookie вообще существует. Если cookie не установлено (первый запрос, блокировка cookies браузером, неверный path/domain), функция сразу падает с ошибкой.

**Дополнительная проблема**: JavaScript в `app.js` (строки 27–38) — функция `addCSRFToForms()` — добавляет CSRF-поле в формы, но **пропускает** формы, у которых уже есть `csrf_token`. Однако на странице регистрации поле уже есть, поэтому это не проблема.

## План исправления

### Шаг 1: Исправить middleware — не генерировать токен на POST

**Файл:** `app/main.py`

Убрать вызов `generate_csrf_token()` для POST-запросов. Токен генерируется только при рендере страницы (GET).

```python
@app.middleware("http")
async def add_csrf_token(request: Request, call_next):
    """Добавить CSRF-токен в контекст шаблонов и установить Cookie для GET-запросов."""
    from app.core.config import get_settings
    
    # Токен генерируем ТОЛЬКО для GET-запросов (при рендере страниц)
    if request.method == "GET":
        csrf_token = generate_csrf_token()
        request.state.csrf_token = csrf_token
        
        response = await call_next(request)
        
        # Установить CSRF Cookie для GET-ответов
        settings = get_settings()
        csrf_cookie_name = settings.session_cookie + "_csrf"
        response.set_cookie(
            key=csrf_cookie_name,
            value=csrf_token,
            httponly=True,
            samesite="lax",
            path="/",
        )
        
        return response
    
    # Для POST и других методов — просто передать запрос дальше
    # (cookie уже установлен предыдущим GET-запросом)
    return await call_next(request)
```

**Почему это исправит проблему:**
- На GET: токен генерируется, устанавливается в state и cookie.
- На POST: токен НЕ генерируется, cookie не перезаписывается. Cookie содержит тот же токен, что и в форме → валидация проходит.

### Шаг 2: Улучшить `verify_csrf_token` — добавить явную обработку ошибок

**Файл:** `app/core/csrf.py`

Добавить более подробное логирование для диагностики:

```python
import logging
logger = logging.getLogger(__name__)

async def verify_csrf_token(request: Request, form: dict = None) -> bool:
    settings = get_settings()
    
    cookie_token = request.cookies.get(settings.session_cookie + "_csrf")
    header_token = request.headers.get("X-CSRF-Token")
    
    # Паттерн 1: заголовок X-CSRF-Token (double-submit cookie)
    if cookie_token and header_token:
        if not secrets.compare_digest(cookie_token, header_token):
            logger.warning("CSRF token mismatch (header)")
            raise HTTPException(
                status_code=status.HTTP_403_FORBIDDEN,
                detail="CSRF token mismatch",
            )
        return True
    
    # Паттерн 2: поле формы csrf_token
    if form:
        form_token = form.get("csrf_token")
        if form_token and cookie_token:
            if secrets.compare_digest(cookie_token, form_token):
                return True
            logger.warning("CSRF token mismatch (form)")
        elif not cookie_token:
            logger.warning("CSRF cookie not found")
        elif not form_token:
            logger.warning("CSRF form token not found. Form keys: %s", list(form.keys()))
    
    raise HTTPException(
        status_code=status.HTTP_403_FORBIDDEN,
        detail="CSRF token missing or invalid",
    )
```

### Шаг 3: Проверить, что форма содержит csrf_token

**Файл:** `app/templates/register.html`

Убедиться, что форма корректно рендерится:

```html
<form action="/register" method="POST" class="auth-form">
    <input type="hidden" name="csrf_token" value="{{ csrf_token }}">
    <!-- ... -->
</form>
```

Это уже есть. Но нужно убедиться, что `csrf_token` передаётся в шаблон.

**Файл:** `app/main.py`, handler `register_page`

```python
@app.get("/register", response_class=HTMLResponse)
async def register_page(request: Request, error: str = None):
    csrf_token = getattr(request.state, "csrf_token", generate_csrf_token())
    return templates.TemplateResponse("register.html", {
        "request": request,
        "error": error,
        "csrf_token": csrf_token,
    })
```

Это тоже корректно.

### Шаг 4: Проверить, что logout не ломает CSRF

**Файл:** `app/main.py`, handler `login_submit`

После успешного входа устанавливается новый CSRF-токен. Это нормально, так как происходит после POST.

Но handler `logout_submit` (`POST /api/auth/logout`) **НЕ** вызывает `csrf_protect_form`. Это уязвимость, но не причина текущей ошибки. Можно исправить отдельно.

## Порядок действий

1. **Исправить middleware** (`app/main.py`) — убрать генерацию токена на POST.
2. **Добавить логирование** в `verify_csrf_token` (`app/core/csrf.py`).
3. **Перезапустить приложение** и проверить регистрацию.
4. Если ошибка сохраняется — посмотреть логи для понимания, какой паттерн не сработал.

## Возможные дополнительные причины

Если после исправления middleware ошибка останется:

1. **Браузер блокирует cookies** — проверить DevTools → Application → Cookies.
2. **Docker-окружение** — проверить, что cookie path/domain корректны.
3. **Кэш страницы** — попробовать очистить кэш и куки браузера.
4. **Старый код** — убедиться, что сервер перезапустился после изменений.
