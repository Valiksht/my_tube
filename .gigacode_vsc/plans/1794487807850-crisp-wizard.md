# План исправления подключения к MinIO

## Проблема

В production-контейнере `mytube_api` код пытается подключиться к MinIO по адресу `localhost:9000`. Внутри контейнера `localhost` — это сам контейнер API, а не сервис MinIO. Правильный адрес MinIO из сети Docker — `minio:9000` (имя сервиса в compose-сети).

**Корень проблемы:** `docker-compose.production.yaml` не передаёт переменную `MINIO_HOST` для сервиса API, а Python-конфиг по умолчанию использует `"localhost"`.

**Цепочка подтверждения:**
1. `config.py:57` — `minio_host: str = "localhost"` — Pydantic `BaseSettings` с `case_sensitive=False` автоматически маппит env-переменную `MINIO_HOST` в атрибут `minio_host`.
2. `config.py:62-64` — свойство `minio_endpoint` возвращает `f"{self.minio_host}:{self.minio_port}"` → при `MINIO_HOST=minio` вернёт `"minio:9000"`.
3. `minio.py:33` — `Minio(settings.minio_endpoint, ...)` — использует это значение для создания S3-клиента.

---

## Изменение

### `docker-compose.production.yaml` — добавить `MINIO_HOST=minio` для API

**Файл:** `docker-compose.production.yaml`, секция `api`, блок `environment`, строка ~122.

**Текущий фрагмент:**
```yaml
      - MINIO_BUCKET=${MINIO_BUCKET:-videos}
      - MINIO_PUBLIC_URL=http://localhost:9000
```

**Станет:**
```yaml
      - MINIO_BUCKET=${MINIO_BUCKET:-videos}
      - MINIO_HOST=minio
      - MINIO_PUBLIC_URL=http://localhost:9000
```

Одна строка: `- MINIO_HOST=minio` между `MINIO_BUCKET` и `MINIO_PUBLIC_URL`.

**Почему не нужно трогать `.env.production`:**
- `MINIO_HOST` — переменная только для Docker-сети, она не должна попадать в `.env`.
- В `docker-compose.yaml` (dev) она тоже задана напрямую в compose, а не в `.env`.
- Следуем существующему паттерну проекта.

## Порядок действий

1. **Применить изменение** — добавить `- MINIO_HOST=minio` в секцию `environment` сервиса `api`.
2. **Пересобрать и перезапустить** API-контейнер: `docker compose -f docker-compose.production.yaml --env-file .env.production up -d --build api`.
3. **Дождаться** healthy-статусов всех сервисов.
4. **Проверить подключение API к MinIO** — убедиться, что в логах нет `Connection refused` на 9000.
5. **Проверить загрузку видео** — POST /upload с файлом `helloween.mp4`.
6. **Проверить воспроизведение** — открыть страницу видео, убедиться, что файл отдаётся.
7. **Проверить публичные URL** — убедиться, что `MINIO_PUBLIC_URL=http://localhost:9000` корректно работает с точки зрения браузера (если приложение открывается не на той же машине, localhost может быть неправильным адресом).
8. **Проверить логи** — `docker compose -f docker-compose.production.yaml logs --tail=200 mytube_api`.

### 🔧 Исправленные проблемы

#### 1. Подключение к MinIO (docker-compose.production.yaml)

**Проблема:** API подключался к `localhost:9000` вместо `minio:9000` внутри Docker-сети.

**Решение:** добавлена строка `- MINIO_HOST=minio` в env переменные сервиса `api`.

#### 2. Загрузка видео через HTML-форму (app/api/pages/video_pages.py)

**Проблема:** HTML-обработчик на строке 140 не передавал `size` в `upload_video_file()`. MinIO SDK требовал размер файла при загрузке, иначе ошибка:
```
valid part size must be provided when object size is unknown
```

**Решение:** добавлен параметр `size=file_size` в вызов `service.upload_video_file()` на строке 140.

API-эндпоинт (`app/api/videos.py`) передавал `size` корректно с самого начала — проблема была только в HTML-форме.

## Риски и известные моменты

- **Bucket policy не устанавливается автоматически.** Служба `minio-init` создаёт бакет, но не устанавливает политику публичного доступа. Код в `app/storage/minio.py` ставит политику только при первом `upload`, если бакет ещё не существует. После первого загруженного видео все subsequent-видео доступны по прямой ссылке.
- **MissingGreenlet:** В async-коде могут быть проблемы с ленивой загрузкой relationship-атрибутов. Если появятся — использовать `selectinload`/`joinedload`.
- **Nginx и статика:** Nginx проксирует всё к API, так что видео отдаются через MinIO без проблем.
- **MINIO_PUBLIC_URL=http://localhost:9000:** Если приложение доступно по другому адресу (не localhost), браузер не сможет получить видео напрямую из MinIO.
