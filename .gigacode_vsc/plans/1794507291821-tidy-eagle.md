# План: Страница «Мои подписки»

## Анализ текущего состояния

**Эндпоинт для страницы «Мои подписки» — НЕ существует.**

Существующая функциональность подписок:
- API-эндпоинт `GET /api/channels/{channel_id}/subscriptions` — список подписчиков канала (не то же самое)
- Сервис `SubscriptionService.get_user_subscriptions(user_id)` — уже возвращает подписки пользователя (есть в `app/services/subscription.py`, строка 74)
- CRUD `subscription_repo.get_user_subscriptions()` — запрос к БД (есть в `app/crud/subscription.py`, строка 25)

База данных уже хранит подписки в таблице `subscriptions` с полями `subscribed_user_id` и `subscribed_channel_id`.

## Что нужно сделать

### 1. HTML-роутер — `app/api/pages/subscriptions_pages.py` (новый файл)

Создать новый модуль с одним маршрутом:

```
GET /my-subscriptions
```

**Логика роутера:**
- Требует авторизацию (`Depends(get_current_user)`)
- Получает список подписок через `SubscriptionService.get_user_subscriptions(user_id)`
- Извлекает связанные каналы из объектов подписок (`subscription.subscribed_channel`)
- Сортирует каналы по имени (алфавитный порядок, A–Я → a–z)
- Передаёт в шаблон список каналов с подписками

**Почему в `channel_pages.py` не стоит:**
`channel_pages.py` отвечает за страницы конкретных каналов и профилей. Страница «Мои подписки» — это отдельная сущность, связанная с текущим пользователем, а не с конкретным каналом. Лучше вынести в отдельный файл `subscriptions_pages.py`.

### 2. Подключение роутера — `app/api/pages/__init__.py`

Добавить импорт и подключение нового роутера:

```python
from app.api.pages.subscriptions_pages import router as subscriptions_pages_router
...
pages_router.include_router(subscriptions_pages_router)
```

### 3. Шаблон — `app/templates/my_subscriptions.html` (новый файл)

Наследует от `base.html`. Содержимое:
- Заголовок «Мои подписки»
- Цикл по каналам: для каждого канала отображается
  - Название канала (ссылка на `/channel/{channel_id}`)
  - Описание канала
  - Количество подписчиков
  - Кнопка «Отписаться» (POST на существующий API-эндпоинт `/api/channels/{channel_id}/subscriptions`)
- Если подписок нет — пустое состояние с сообщением «Вы пока не подписаны ни на один канал»

### 4. Ссылка в навбаре — `app/templates/base.html`

Добавить ссылку «Подписки» в навигацию рядом со ссылкой «Профиль»:

```html
<a href="/my-subscriptions" class="nav-link">Подписки</a>
```

Разместить после ссылки «Профиль», перед именем пользователя.

### 5. Стили — `app/static/css/style.css`

Добавить минимальные стили для страницы подписок:
- `.subscriptions-page` — контейнер страницы
- `.subscription-channel-card` — карточка канала в списке
- `.subscription-channel-card .channel-name` — название канала
- `.subscription-channel-card .channel-description` — описание
- `.subscription-channel-card .channel-meta` — мета-информация (количество подписчиков)
- Возможно небольшой блок стилей для пустого состояния

## Архитектурные решения

- **Использовать существующий сервис** `SubscriptionService.get_user_subscriptions()` — не нужно создавать новый сервис или CRUD-метод
- **Сортировка на Python** — каналы загружаются через relationship `subscribed_channel`, сортировка `.sort(key=lambda x: x.subscribed_channel.name)` — это просто и эффективно для списка подписок одного пользователя
- **Отписка через существующий API** — кнопка «Отписаться» отправляет POST на `/api/channels/{channel_id}/subscriptions` (toggle), JavaScript в `app.js` уже умеет обрабатывать такие кнопки
- **Страница доступна только авторизованным** — используется `Depends(get_current_user)`, анонимный пользователь получит 401
