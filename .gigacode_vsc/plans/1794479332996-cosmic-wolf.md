# План проверки и исправления приложения YouTube Clone

## Итог проверки

Приложение импортируется без ошибок, архитектура модульная и понятная.
Найдено **14 проблем** — 3 критических (блокируют работу), 5 средних (баги), 6 мелких (качество кода).

---

## Критические проблемы (блокируют работу)

### P0-1. Дублирование маршрута `/api/auth/logout`

**Файлы:** `app/api/auth.py` (строка 122) и `app/api/pages/auth_pages.py` (строка 162)

Оба роутера определяют POST `/api/auth/logout`. Это конфликт маршрутов — FastAPI может игнорировать один из них или вести себя непредсказуемо.

**Исправление:** Удалить дубликат из `auth_pages.py`. Страница не нужна — logout выполняется через API-запрос с фронтенда.

---

### P0-2. `response_class="HTMLResponse"` как строка в `/login`

**Файл:** `app/api/pages/auth_pages.py`, строка 30

```python
@router.get("/login", response_class="HTMLResponse")
```

Строка `"HTMLResponse"` вместо класса `HTMLResponse`. Вызывает ошибку при генерации OpenAPI-схемы:
`AttributeError: 'str' object has no attribute 'media_type'`

**Исправление:** Заменить на `response_class=HTMLResponse`.

---

### P0-3. Lazy load relationship в `upload_submit`

**Файл:** `app/api/pages/video_pages.py`, строки 107 и 115

```python
channel = await channel_repo.get_by_id(db, channel_id)  # без eager load
...
if channel.user.id != current_user.id:  # lazy load Channel.user
```

`get_by_id` не загружает relationship `user`. В асинхронном SQLAlchemy lazy load вызывает ошибку.

**Исправление:** Использовать `get_by_id_with` с `selectinload(Channel.user)` или использовать `current_user.channel` (уже загружен через `get_current_user`).

---

## Средние проблемы (баги)

### P1-1. `UploadFile = None` без Optional

**Файл:** `app/api/videos.py`, строка 108

```python
video_file: UploadFile = None,
```

FastAPI некорректно обрабатывает `None` как default для `UploadFile`.

**Исправление:** `video_file: UploadFile | None = None,`

---

### P1-2. `ReportResolve = None` без Optional

**Файл:** `app/api/moderation.py`, строка 93

```python
resolve_data: ReportResolve = None,
```

**Исправление:** `resolve_data: ReportResolve | None = None,`

---

### P1-3. `data: dict` без Pydantic-схемы

**Файл:** `app/api/channels.py`, строка 167

```python
async def update_me(data: dict, ...):
```

Отсутствует валидация входных данных.

**Исправление:** Использовать `UserUpdate` схему или `dict[str, Any]` с явным указанием типа.

---

### P1-4. `JSONResponse` со статусом 204

**Файл:** `app/api/auth.py`, строки 137 и 142

```python
return JSONResponse(status_code=status.HTTP_204_NO_CONTENT)
```

204 No Content не должен иметь body. `JSONResponse` создаёт пустой JSON body.

**Исправление:** `from fastapi.responses import Response` и `Response(status_code=204)`.

---

### P1-5. `channel.user` без eager load в `get_video`

**Файл:** `app/services/video.py`, строка 162

```python
video = await video_repo.get_by_id_with(
    self.db, video_id, selectinload(Video.channel),
)
...
return video.channel.user.id == current_user.id  # в _check_access
```

Загружается `Video.channel`, но не `Channel.user`. При доступе к `channel.user` — lazy load ошибка.

**Исправление:** Добавить `selectinload(Channel.user)` в запрос.

---

### P1-6. `channel.user` без eager load в `update_video`

**Файл:** `app/services/video.py`, строка 257

```python
if current_user and video.channel.user.id != current_user.id:
```

Та же проблема — `video.channel` загружен, но `channel.user` нет.

**Исправление:** Добавить `selectinload(Channel.user)` в `get_video`.

---

## Мелкие проблемы (качество кода)

### P2-1. Дублирование `__all__` и docstring в моделях

**Файлы:** `users.py`, `channel.py`, `video.py`, `comment.py`, `like.py`, `subscription.py`

Каждая модель содержит `__all__` и docstring в начале и в конце файла.

**Исправление:** Удалить дублирующиеся строки в конце файлов.

---

### P2-2. Мёртвый глобальный `*_service` в сервисах

**Файлы:**
- `app/services/comment.py`, строка 98
- `app/services/like.py`, строка 87
- `app/services/subscription.py`, строка 118
- `app/services/moderation.py`, строка 226

```python
comment_service = CommentService(None)  # type: ignore[arg-type]
```

Никогда не используются, создают экземпляр с `None` как db.

**Исправление:** Удалить эти строки.

---

### P2-3. `is_moderator` без логики проверки

**Файл:** `app/api/videos.py`, строки 297-298

```python
is_moderator: bool = False,
```

Параметр передаётся в `delete_comment`, но нигде не используется для реальной проверки прав.

**Исправление:** Либо удалить параметр, либо добавить зависимость `require_moderator_or_admin()`.

---

### P2-4. `validate_secret_key` никогда не срабатывает

**Файл:** `app/core/config.py`, строка 69

```python
if v == "..." and not cls.model_config.get("env_file"):
```

`model_config` — это class dict, а не instance. Проверка `not cls.model_config.get("env_file")` всегда `False` потому что `model_config` содержит `SettingsConfigDict`, а не `None`.

**Исправление:** Упростить проверку: `if v == "..." and settings.model_config.get("env_file") is not None` или просто убрать предупреждение.

---

### P2-5. `_session_maker` с `bind=None`

**Файл:** `app/database/session.py`, строки 35-39

```python
_session_maker = async_sessionmaker(
    bind=None,  # Будет установлено в get_async_session
    ...
)
```

`bind=None` не нужен — bind устанавливается в `get_async_session` при создании сессии.

**Исправление:** Убрать `bind=None` из `async_sessionmaker`.

---

### P2-6. `success` параметр без обработки на страницах

**Файлы:** `video_pages.py` (строка 158), `channel_pages.py` (строки 90, 165)

```python
return RedirectResponse(f"/video/{video.id}?success=Видео успешно загружено!", ...)
```

Шаблон `video.html` не обрабатывает query-параметр `success`.

**Исправление:** Добавить обработку `success` в шаблоны или использовать flash-сообщения.
