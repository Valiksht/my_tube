# План исправления ошибки подключения к PostgreSQL

## Диагностика

### Найденная проблема

Ошибка **"Не удалось подключиться к PostgreSQL после 30 попыток"** возникает в скрипте
`scripts/docker_entrypoint_production.sh` на строке 26.

**Корневая причина:** в production-образе **отсутствует утилита `pg_isready`**.

Скрипт entrypoint использует `pg_isready` для проверки готовности PostgreSQL:

```bash
while ! pg_isready -h "${DB_HOST}" -p "${DB_PORT}" -U "${DB_USER}" > /dev/null 2>&1; do
```

Однако в `Dockerfile.production` (строка 25-29) устанавливаются только:
```dockerfile
RUN apt-get update && apt-get install -y --no-install-recommends \
    curl \
    libpq5 \
    && rm -rf /var/lib/apt/lists/* \
    && apt-get clean
```

Утилита `pg_isready` находится в пакете `postgresql-client`, который **не установлен**
в production-образе. При этом в development-образе (`Dockerfile`, строка 4-8) он есть:
```dockerfile
RUN apt-get update && apt-get install -y \
    gcc \
    libpq-dev \
    postgresql-client \
    && rm -rf /var/lib/apt/lists/*
```

### Почему `pg_isready` не работает

Когда команда `pg_isready` отсутствует, bash выполняет:
```bash
pg_isready ... > /dev/null 2>&1
```

Результат — код выхода **127** (команда не найдена). Цикл `while ! ...` интерпретирует
это как "не готово" и продолжает повторяться 30 раз с интервалом 2 секунды,
после чего выходит с ошибкой.

### Дополнительные проблемы

1. **Парсинг DATABASE_URL в entrypoint** — строки 22-24 извлекают параметры из
   `DATABASE_URL` через `sed`. URL имеет формат:
   ```
   postgresql+asyncpg://postgres:postgres@postgres:5432/mytube_db
   ```
   Регулярные выражения `sed` могут некорректно распарсить URL из-за присутствия
   `+asyncpg` после `postgresql:`. Это может привести к неверному извлечению
   `DB_HOST`, `DB_PORT` или `DB_USER`.

2. **Alembic использует статический URL из alembic.ini** — в `alembic.ini` (строка 9)
   жёстко прописан URL `postgresql+asyncpg://postgres:postgres@localhost:5432/mytube_db`.
   При запуске `alembic upgrade head` внутри контейнера alembic может использовать
   этот URL вместо `DATABASE_URL`, если `env.py` не передаёт переменную окружения.
   Однако `env.py` (строка 37) читает `DATABASE_URL` из окружения, так что это
   работает корректно.

## План исправлений

### Исправление 1: Добавить postgresql-client в Dockerfile.production

**Файл:** `Dockerfile.production`
**Строка:** 25-29

Добавить `postgresql-client` в список устанавливаемых пакетов:

```dockerfile
RUN apt-get update && apt-get install -y --no-install-recommends \
    curl \
    libpq5 \
    postgresql-client \
    && rm -rf /var/lib/apt/lists/* \
    && apt-get clean
```

### Исправление 2: Исправить парсинг DATABASE_URL в entrypoint

**Файл:** `scripts/docker_entrypoint_production.sh`
**Строки:** 22-24

Заменить извлечение параметров из `DATABASE_URL` на использование прямых переменных
окружения, которые уже определены в `docker-compose.production.yaml`:

```bash
# Используем переменные окружения напрямую вместо парсинга DATABASE_URL
DB_HOST="${POSTGRES_HOST:-postgres}"
DB_PORT="${POSTGRES_PORT:-5432}"
DB_USER="${POSTGRES_USER:-postgres}"
```

Также добавить переменную `POSTGRES_HOST` в секцию `environment` сервиса `api`
в `docker-compose.production.yaml` (строка 102-121):

```yaml
environment:
  - DEBUG=False
  - POSTGRES_HOST=postgres
  - POSTGRES_USER=${POSTGRES_USER:-postgres}
  - POSTGRES_PASSWORD=${POSTGRES_PASSWORD:-postgres}
  ...
```

### Итоговый порядок действий

1. Добавить `postgresql-client` в `Dockerfile.production`
2. Добавить `POSTGRES_HOST=postgres` в environment сервиса `api` в `docker-compose.production.yaml`
3. Заменить парсинг `DATABASE_URL` на использование переменных `POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_USER` в `scripts/docker_entrypoint_production.sh`
4. Пересобрать и запустить: `docker compose -f docker-compose.production.yaml up --build`

## Проверка результата

После исправлений лог запуска должен содержать:
- `✅ PostgreSQL готов!`
- `✅ Миграции применены успешно!`
- `✅ Приложение готово к работе!`

HTTP-эндпоинт `/health` должен возвращать `{"status": "ok", "app": "YouTube Clone"}`.
