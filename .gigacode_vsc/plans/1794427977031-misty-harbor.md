## КРИТИЧЕСКИЕ ПРОБЛЕМЫ (блокируют работу)

### 1. HTML-загрузка видео НЕ загружает файлы (main.py:312-353)

**Файл:** `app/main.py`, роут `POST /upload`

**Проблема:** Форма извлекает `video_file` и `thumbnail_file` из формы, но НИКОГДА не вызывает `service.upload_video_file()` или `service.upload_thumbnail()`. Создаётся только запись в БД, файлы не загружаются.

**Функционал:** Загрузка видео через HTML-форму (`/upload`) НЕ работает. Файлы не попадают в хранилище.

**Решение:** Добавить вызовы `upload_video_file()` и `upload_thumbnail()` в роут `/upload`.

---

### 2. API-эндпоинты auth имеют сломанную зависимость `db` (auth.py:43, 79, 135)

**Файл:** `app/api/auth.py`

**Проблема:** В функциях `register()`, `login()`, `logout()` переменная `db` определяется внутри тела функции как `db: AsyncSession = Depends(get_db)`. Это НЕ работает как зависимость FastAPI — `Depends()` должен быть в сигнатуре функции, а не внутри тела.

**Результат:** `db` будет объектом `Depends(...)`, а не реальной сессией БД. Все операции с БД в этих эндпоинтах сломаются.

**Решение:** Переписать зависимости через `Depends(get_db)` в сигнатуре функции или использовать `async for db in get_db():`.

---

### 3. `is_active` в UserSession — тип String, но сравнивается с bool и str

**Файл:** `app/models/session.py:51`, `app/services/auth.py:131`, `app/dependencies.py:50`

**Проблема:**
- Модель: `is_active: Mapped[str] = mapped_column(String(1), default="1")`
- AuthService: `UserSession.is_active == "1"` — сравнивает со строкой
- AuthService.logout: `session.is_active = "0"` — присваивает строку
- Dependencies: `UserSession.is_active == "1"` — сравнивает со строкой

**Результат:** В PostgreSQL `String(1)` хранит `"1"`/`"0"`, но тип `String` для булевого флага — плохая практика. Если миграция создаст column с `BOOLEAN`, сравнения со строками сломаются.

**Решение:** Либо использовать `Boolean`, либо оставить `String(1)` но задокументировать решение. Рекомендуется `Boolean`.

---

### 4. Local docker-compose.yaml НЕ содержит API-контейнер

**Файл:** `docker-compose.yaml`

**Проблема:** Файл содержит только postgres, minio, minio-init. Нет контейнера с API. Нет возможности запустить полный стек локально через `docker-compose up`.

**Решение:** Добавить сервис `api` с build контекстом и правильными переменными окружения (включая `DATABASE_URL` с `postgres` как хостом, `STORAGE_TYPE=minio`, `MINIO_PUBLIC_URL=http://minio:9000`).

---

### 5. Local docker-compose.yaml не устанавливает `STORAGE_TYPE`

**Файл:** `docker-compose.yaml`

**Проблема:** Нет переменной `STORAGE_TYPE`. API по умолчанию не знает, какое хранилище использовать. Без этого `VideoService.storage` будет `None`, и загрузка видео упадёт с `RuntimeError("Storage not configured")`.

**Решение:** Добавить `STORAGE_TYPE=minio` в environment сервиса api.

---

### 6. MinIO образы разные в local и production

**Файл:** `docker-compose.yaml` vs `docker-compose.production.yaml`

**Проблема:**
- Local: `dockerhub.timeweb.cloud/bitnamilegacy/minio:latest` + `mc` client
- Production: `dockerhub.timeweb.cloud/bitnamilegacy/minio:latest` + Bitnami startup scripts

Local использует `mc` (minio-client) для инициализации бакета. Production использует Bitnami-скрипты (`MINIO_DEFAULT_BUCKETS`). Это разные подходы к инициализации.

**Решение:** Унифицировать образы и подходы к инициализации.

## СРЕДНИЕ ПРОБЛЕМЫ

### 7. `alembic.ini` имеет хардкод-URL для локальной БД

**Файл:** `alembic.ini:13`

```ini
sqlalchemy.url = postgresql+asyncpg://postgres:postgres@localhost:5432/mytube_db
```

**Проблема:** При запуске `alembic upgrade head` в Docker используется `env.py`, который читает `DATABASE_URL` из переменных окружения — это работает. Но локально всегда используется хардкод-URL.

**Решение:** Добавить поддержку `DATABASE_URL` из env в `alembic.ini` через `${DATABASE_URL}`.

---

### 8. Health-check не проверяет БД

**Файл:** `Dockerfile.production:53-54`

```dockerfile
HEALTHCHECK CMD curl -f http://localhost:8000/health || exit 1
```

**Проблема:** Эндпоинт `/health` возвращает `{"status": "ok"}` без проверки БД. Контейнер помечается как healthy даже если БД недоступна.

**Решение:** Добавить проверку БД в health-check (например, отдельный эндпоинт `/health/db` или проверить внутри `/health`).

---

### 9. CORS не включает Nginx-домен

**Файл:** `app/core/config.py:44`

```python
cors_origins: str = "http://localhost:3000,http://127.0.0.1:8000,http://localhost:8000"
```

**Проблема:** В production Nginx работает на порту 80. Если frontend делает запросы на `http://localhost:80`, они будут заблокированы CORS.

**Решение:** Добавить `http://localhost:80` в CORS origins.

---

### 10. `__import__` в dependencies.py

**Файл:** `app/dependencies.py:51-52, 92-93`

```python
UserSession.expires_at > __import__("datetime").datetime.now(
    __import__("datetime").timezone.utc
),
```

**Проблема:** Использование `__import__` внутри запроса — плохая практика, затрудняет чтение и отладку.

**Решение:** Импортировать `datetime` в начале файла.

---

### 11. Глобальные синглтоны с `None`

**Файлы:** `app/services/video.py:344`, `app/services/auth.py:183`

```python
video_service = VideoService(None)  # type: ignore[arg-type]
auth_service = AuthService(None)  # type: ignore[arg-type]
```

**Проблема:** Глобальные экземпляры с `db=None` могут быть случайно использованы.

**Решение:** Удалить, если не используются.

### 12. Нет эндпоинта для создания канала

**Проблема:** Пользователь не может создать канал через API. В `main.py:334-337` при загрузке видео проверяется `current_user.channel`, и если канала нет — выдаётся ошибка. Но нет эндпоинта `POST /api/channels` для создания.

**Решение:** Проверить, есть ли эндпоинт создания канала, и если нет — добавить.

### 14. MinIO public policy закомментирован

**Файл:** `app/storage/minio.py:80`

```python
# self.client.set_bucket_policy(self.bucket, json.dumps(policy))
```

Бакет создаётся, но публичный доступ не устанавливается программно. В local docker-compose это делается через `mc anonymous set download` в init-контейнере.

### 15. `STORAGE_TYPE` не в Settings

**Файл:** `app/core/config.py`

Переменная `STORAGE_TYPE` передаётся в окружение, но не читается в `Settings`. Storage выбирается на уровне импорта (`from app.storage.minio import storage`).

### Причина падения production-стека

postgres exited (1) — вероятные причины:
1. Образ `postgres:15-alpine` не может инициализировать БД из-за прав на volume
2. Конфликт с существующими данными в volume `postgres_data`
3. Healthcheck не проходит из-за таймаута

minio exited (0) — образ Bitnami-minified может некорректно работать на Windows/Docker Desktop.
