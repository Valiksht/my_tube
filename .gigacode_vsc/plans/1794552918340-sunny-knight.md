# План исправления ошибок проекта YouTube Clone

## Выявленные проблемы

### 1. `nc` (netcat) отсутствует в образе `garage-init` (КРИТИИЧЕСКАЯ)
**Файл:** `Dockerfile.garage-init`

Скрипт `garage_init.sh` использует `nc -z` для проверки доступности Garage, но образ `busybox:latest` не содержит netcat. Скрипт падает на первой же проверке порта.

**Решение:** Добавить установку netcat в Dockerfile.garage-init.

### 2. Инвертированная логика в `s3_retry` (КРИТИЧЕСКАЯ)
**Файл:** `scripts/garage_init.sh`

Функция `s3_retry` имеет инвертированную логику:
```bash
# Текущий (НЕПРАВИЛЬНЫЙ) код:
while eval "$cmd" 2>&1; do      # Условие: команда УСПЕШНА
    echo "$desc — успешно"        # Выходим при УСПЕХЕ (нелогично)
    return 0
done
# А здесь retry — но условие while уже FALSE (команда НЕУДАЧНА)
while true; do
    ...
    if eval "$cmd" 2>&1; then    # Если команда УСПЕШНА — выходим
        echo "$desc — успешно"
        return 0
    fi
done
```

Проблема: первый `while eval "$cmd"` выполняется когда команда НЕУДАЧНА (условие while = false), поэтому он сразу переходит к retry-циклу. Но retry-цикл работает правильно — проблема только в лишнем первом блоке.

**Решение:** Упростить функцию — удалить первый блок, оставить только retry-цикл.

### 3. Проверка готовности S3 API вместо RPC
**Файл:** `scripts/garage_init.sh`

Скрипт проверяет порт 3900 (S3 API), но команды `garage status`, `garage layout` и `garage bucket` используют RPC-порт 3901. S3 API может быть доступен раньше, чем RPC готов к cluster layout.

**Решение:** Добавить проверку RPC-порта 3901 перед выполнением garage-команд.

### 4. Видео-стриминг всегда возвращает 206
**Файл:** `app/api/pages/video_pages.py` (функция `stream_video`)

Когда клиент НЕ отправляет Range header (первый запрос), функция всё равно возвращает статус 206. Браузеры ожидают 200 для полного файла при первом запросе без Range.

**Решение:** Возвращать 200 когда нет Range header, 206 — только при Range запросе.

### 5. Nginx volume mount не соответствует пути API
**Файл:** `docker-compose.production.yaml`

Nginx монтирует `storage_data:/usr/share/nginx/storage`, но API сохраняет файлы в `/app/storage`. Nginx не может обслуживать загруженные файлы.

**Решение:** Изменить mount point nginx на `/app/storage` или создать symlink.

## План исправлений

### Шаг 1: Исправить `Dockerfile.garage-init`
Добавить установку `netcat-openbsd` для работы `nc -z`:

```dockerfile
FROM busybox:latest

RUN apk add --no-cache netcat-openbsd

COPY --from=garage-binary /garage /usr/local/bin/garage
COPY garage-init.toml /etc/garage.toml
COPY scripts/garage_init.sh /init.sh
RUN chmod +x /init.sh

ENTRYPOINT ["/init.sh"]
```

### Шаг 2: Исправить `scripts/garage_init.sh`

#### 2a. Упростить функцию `s3_retry`

Заменить текущую функцию на:
```bash
s3_retry() {
    local cmd="$1"
    local desc="$2"
    local max_retries=30
    local retry_count=0
    
    while true; do
        retry_count=$((retry_count + 1))
        if [ $retry_count -ge $max_retries ]; then
            echo "Ошибка: Не удалось $desc после ${max_retries} попыток"
            return 1
        fi
        echo "$desc: попытка $retry_count/$max_retries..."
        if eval "$cmd" 2>&1; then
            echo "$desc — успешно"
            return 0
        fi
        sleep 5
    done
}
```

#### 2b. Добавить проверку RPC-порта

Добавить проверку порта 3901 (RPC) перед выполнением garage-команд:

```bash
# --- Ожидание готовности RPC ---
echo ""
echo "Ожидание готовности Garage RPC (порт 3901)..."

RPC_MAX_RETRIES=60
RPC_RETRY_COUNT=0

while ! nc -z -w2 $GARAGE_HOST 3901 2>/dev/null; do
    RPC_RETRY_COUNT=$((RPC_RETRY_COUNT + 1))
    
    if [ $RPC_RETRY_COUNT -ge $RPC_MAX_RETRIES ]; then
        echo "Ошибка: Не удалось подключиться к Garage RPC после ${RPC_MAX_RETRIES} попыток"
        exit 1
    fi
    
    sleep 2
done

echo "Garage RPC готов!"
```

Этот блок нужно вставить после проверки S3-порта (3900) и перед проверкой cluster layout.

### Шаг 3: Исправить `app/api/pages/video_pages.py`

В функции `stream_video` изменить статус ответа:

```python
# Вместо:
return StreamingResponse(
    iter_content(),
    status_code=206,
    headers=headers,
)

# Стало:
if range_header:
    return StreamingResponse(
        iter_content(),
        status_code=206,
        headers=headers,
    )
else:
    return StreamingResponse(
        iter_content(),
        status_code=200,
        headers=headers,
    )
```

Также нужно переместить формирование headers внутрь условных блоков, так как `Content-Range` и `Accept-Ranges` нужны только для 206.

### Шаг 4: Исправить `docker-compose.production.yaml`

Изменить volume mount для nginx:

```yaml
  nginx:
    image: nginx:alpine
    container_name: mytube_nginx
    ports:
      - "${NGINX_PORT:-80}:80"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
      - storage_data:/app/storage:ro   # Было: /usr/share/nginx/storage
    depends_on:
      - api
    networks:
      - mytube_network
    restart: unless-stopped
```

Или изменить nginx.conf для соответствия текущему mount:

```nginx
location /storage/ {
    alias /app/storage/;
    expires 30d;
    add_header Cache-Control "public, immutable";
}
```
