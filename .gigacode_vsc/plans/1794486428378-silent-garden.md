# План создания тестов для HTTP эндпоинтов

## Цель

Написать тесты для всех существующих HTTP эндпоинтов проекта, которые ещё не покрыты тестами.
Каждый эндпоинт должен минимально проверяться — не завершаться ошибкой.
POST-эндпоинты проверяют, что запрос выполняется (возвращает статус без исключения).

## Текущее состояние

**Написанные тесты (17 тестов, 2 файла):**
- `tests/test_auth.py` — 9 тестов (register, login, me, health)
- `tests/test_videos.py` — 8 тестов (list, get, create, update, delete, search)

- Комментарии: 3 эндпоинта

## Важные замечания

1. **Аутентификация в тестах**: Для эндпоинтов с авторизацией сначала выполняем POST /api/auth/login, затем используем returned access_token как cookie.

2. **Метод установки cookie**: Как в существующих тестах:
   ```python
   client.cookies.set("session", login_response.json()["access_token"], domain="test")
   ```

3. **CSRF**: HTML-страницы используют CSRF-защиту для POST-форм. Для тестов POST-страниц можно:
   - Сначала получить страницу (GET) и извлечь CSRF-токен
   - Отправить POST с токеном
   - Или проверить что POST без токена возвращает 403/400

4. **Модерация**: Для тестов модерации нужен пользователь с ролью moderator. Добавить фикстуру `moderator_user` в conftest.py.

5. **Хранение**: Эндпоинт `/api/videos/upload` зависит от MinIO. Тесты без файла должны работать без MinIO. Тесты с файлом могут потребовать мокирования storage.

6. **Не менять conftest.py без необходимости**: Добавлять только новую фикстуру `moderator_user`.
