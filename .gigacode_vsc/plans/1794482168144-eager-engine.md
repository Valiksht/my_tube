# Отчёт: Настройка MinIO для загрузки и просмотра видео

## Описание ошибки

При попытке загрузки видео возникает ошибка:

```
HTTPConnectionPool(host='localhost', port=80): Max retries exceeded with url: /videos?location=
(Caused by NewConnectionError("HTTPConnection(host='localhost', port=80): Failed to establish a new connection: [Errno 111] Connection refused"))
```

## Анализ

### 1. Порт подключения

Ошибка указывает на подключение к `localhost:80`, но приложение работает на порту `8000`.
Это означает, что запрос отправляется не с HTML-формы, а из внешнего источника — curl, Postman или другой инструмент.

### 2. Конфигурация хранилища

**Ключевая проблема:** Локальный `docker-compose.yaml` использует `STORAGE_TYPE=filesystem`.
Сервис MinIO вообще не определён. Видео сохраняются на диск контейнера, а не в S3-хранилище.

### 3. Архитектура видео-потока

```
[Браузер] → POST /upload (port 8000, FastAPI)
  → [API] создаёт запись в БД
  → [API] загружает файл в MinIO (port 9000)
  → [API] возвращает URL: http://localhost:9000/videos/videos/{object_name}

[Браузер] → GET /video/{id} (port 8000, FastAPI)
  → [API] возвращает HTML с <video src="http://localhost:9000/videos/videos/...">

[Браузер] → GET http://localhost:9000/videos/videos/{object_name} (port 9000, MinIO)
  → [MinIO] отдаёт видеофайл напрямую браузеру
```

### 4. Найденные проблемы

**Проблема 1:** Нет сервиса MinIO в локальном docker-compose.yaml
**Проблема 2:** STORAGE_TYPE=filesystem вместо minio
**Проблема 3:** Нет init-контейнера для создания бакета
**Проблема 4:** Нет healthcheck для MinIO
**Проблема 5:** Нет переменных MINIO_ROOT_USER/PASSWORD в API
**Проблема 6:** API зависит от postgres, но не от minio

### 5. Реализация хранилищ

**MinIO storage (`app/storage/minio.py`):**
- Корректно работает с MinIO SDK
- Возвращает URL в формате `{public_url}/{bucket}/{object_name}`
- Методы async вызывают синхронные методы SDK (не блокирует для тестов)

## План исправлений

### Шаг 1: Изменить docker-compose.yaml

Добавить сервис MinIO и изменить конфигурацию API.

**Важно:** Используем Bitnami-специфичные переменные. Не меняем образ на `minio/minio`.

#### 1.1 Добавить сервис `minio`

```yaml
  minio:
    image: dockerhub.timeweb.cloud/bitnamilegacy/minio:latest
    container_name: mytube_minio_local
    environment:
      - MINIO_ROOT_USER=minioadmin
      - MINIO_ROOT_PASSWORD=minioadmin
      - MINIO_DEFAULT_BUCKETS=videos
    ports:
      - "9000:9000"
      - "9001:9001"
    volumes:
      - minio_data:/data
    healthcheck:
      test: ["CMD", "curl", "-fsS", "http://127.0.0.1:9000/minio/health/live"]
      interval: 5s
      timeout: 5s
      retries: 20
      start_period: 30s
    networks:
      - mytube_network
    restart: unless-stopped
```

Ключевые моменты:
- Образ: `dockerhub.timeweb.cloud/bitnamilegacy/minio:latest` (не менять)
- Переменные: `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD`, `MINIO_DEFAULT_BUCKETS` (Bitnami-специфичные)
- Volume: `/data` (Bitnami-стандарт)
- Healthcheck: штатный `curl` к `/minio/health/live`
- UID 1001: Bitnami-образ запускается от этого UID по умолчанию, явно не указываем

#### 1.2 Добавить сервис `minio-init`

```yaml
  minio-init:
    image: dockerhub.timeweb.cloud/bitnamilegacy/minio-client:latest
    container_name: mytube_minio_init_local
    environment:
      - MINIO_SERVER_HOST=minio
      - MINIO_SERVER_PORT_NUMBER=9000
      - MINIO_SERVER_SCHEME=http
      - MINIO_SERVER_ROOT_USER=minioadmin
      - MINIO_SERVER_ROOT_PASSWORD=minioadmin
    depends_on:
      minio:
        condition: service_healthy
    command:
      - /opt/bitnami/scripts/minio-client/run.sh
      - mb
      - --ignore-existing
      - minio/videos
    networks:
      - mytube_network
    restart: "no"
```

#### 1.3 Изменить сервис `api`

Заменить:
```yaml
      - STORAGE_TYPE=filesystem
      - STORAGE_DIR=/app/storage
```

На:
```yaml
      - STORAGE_TYPE=minio
      - STORAGE_DIR=/app/storage
      - MINIO_ROOT_USER=minioadmin
      - MINIO_ROOT_PASSWORD=minioadmin
      - MINIO_BUCKET=videos
      - MINIO_PUBLIC_URL=http://localhost:9000
      - MINIO_SECURE=false
```

Добавить зависимость:
```yaml
    depends_on:
      postgres:
        condition: service_healthy
      minio-init:
        condition: service_completed_successfully
```

#### 1.4 Добавить volume `minio_data`

В секцию `volumes` добавить:
```yaml
  minio_data:
```

### Шаг 2: Проверить что всё работает

1. Запустить `docker compose up -d --build`
2. Проверить что все контейнеры запущены: `docker compose ps`
3. Проверить логи MinIO: `docker compose logs minio`
4. Загрузить тестовое видео через `/upload`
5. Проверить что видео появляется на странице `/video/{id}`
6. Проверить воспроизведение видео в браузере
