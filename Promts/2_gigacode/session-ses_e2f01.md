**НАЙДЕНА КОРНЕВАЯ ПРИЧИНА!**

MinIO возвращает `Access Denied`:

```xml
<Error>
  <Code>AccessDenied</Code>
  <Message>Access Denied.</Message>
  <Key>videos/11.mp4</Key>
  <BucketName>videos</BucketName>
  <Resource>/videos/videos/11.mp4</Resource>
</Error>
```

Файл существует в MinIO, но **бакет не имеет публьного доступа**.

**Почему это произошло:**

1. `minio-init` создаёт бакет `videos` при старте Docker (без публьной политики)
2. В `minio.py` код установки публичной политики запускается ТОЛЬКО если бакет НЕ существует:
   ```python
   if not self.client.bucket_exists(self.bucket):
       self.client.make_bucket(self.bucket)
       # политика устанавливается только здесь
   ```
3. Бакет уже существует → политика не устанавливается → файлы недоступны публично

## Результат

**Проблема найдена и исправлена.**

### Корневая причина

MinIO бакет `videos` не имел публьного доступа. Файл загружался, но браузер получал `403 Access Denied` при попытке воспроизвести видео.

**Почему:** `minio-init` создаёт бакет без политики публьного доступа. Приложение устанавливало политику только при создании нового бакета, но бакет уже существовал — политика никогда не применялась.

### Что исправлено

**Файл:** `app/storage/minio.py` (строки 63-81)

Политика публьного доступа теперь устанавливается при КАЖДОЙ загрузке файла, а не только при создании бакета.

### Проверка

```
Video 11 (Halloween.mp4):
  HTTP Status: 200
  Content-Type: video/mp4
  Size: 7 978 127 bytes
```

### Что сделать сейчас

1. Откройте `http://localhost:8000/video/11` в браузере
2. Видео должно воспроизводиться

Все будущие загрузки видео будут автоматически доступны, так как код теперь всегда устанавливает правильную политику бакета.
