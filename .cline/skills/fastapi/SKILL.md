# Навык разработки на FastAPI

Этот навык описывает, как я хочу разрабатывать
API для своего YouTube Clone.

## Перед началом работы

1. Изучи существующий endpoint или модуль.
2. Посмотри, как организованы похожие функции.
3. Проверь существующие зависимости.
4. Не создавай новый способ реализации,
   если в проекте уже есть подходящий.

## Создание endpoint

Endpoint должен быть максимально простым.

Его задачи:
- Получить данные запроса.
- Получить необходимые зависимости.
- Вызвать сервис.
- Вернуть ответ.

Не размещай сложную бизнес-логику в endpoint.

## Dependencies

Используй Depends для:
- Получения текущего пользователя.
- Проверки ролей.
- Получения сессии БД.
- Проверки существования объектов.
- Проверки доступа.

Если объект уже получен в dependency,
не запрашивай его повторно без необходимости.

## Services

В сервисах размещай бизнес-логику.

Сервис должен отвечать за конкретную задачу.

Не смешивай в одном сервисе несвязанные функции.

## Pydantic

Используй Pydantic для:
- Проверки входных данных.
- Формирования ответов.
- Ограничений значений.
- Валидации данных.

Не возвращай SQLAlchemy-модели напрямую
из API без необходимости.

## HTTP-статусы

Подбирай правильные HTTP-статусы.

Не используй 200 для всех ответов.
Не используй 500 для ошибок пользователя.

## Документация

Добавляй понятные docstring и описания endpoint.

Используй response_model, где это необходимо.

## Проверка результата

После реализации:
1. Проверь импорты.
2. Проверь работу endpoint.
3. Проверь успешный запрос.
4. Проверь ошибочные запросы.
5. Проверь отсутствие авторизации.
6. Проверь недостаток прав.

Если меняется существующий API,
не ломай его без необходимости.
