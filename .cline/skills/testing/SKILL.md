# Навык тестирования

Я хочу, чтобы проект проверялся автоматически,
а не только вручную через Swagger.

Используй pytest и httpx.

## Перед написанием тестов

1. Изучи существующие тесты.
2. Проверь настройки тестовой БД.
3. Посмотри существующие fixtures.
4. Используй уже имеющиеся вспомогательные функции.
5. Не создавай дублирующие fixtures.

## Что тестировать

Для каждого нового функционального модуля
проверяй:

- Успешный сценарий.
- Некорректные входные данные.
- Отсутствие авторизации.
- Недостаток прав.
- Отсутствие запрашиваемого объекта.
- Конфликты данных.
- Ошибки внешних сервисов.

## Работа с базой данных

Тесты не должны использовать настоящую
рабочую базу данных.

Используй отдельную тестовую БД.

После тестов данные должны очищаться.

Не допускай, чтобы тесты зависели
от порядка выполнения друг друга.

## Проверка безопасности

Особое внимание уделяй:
- Доступу к чужим видео.
- Изменению чужих видео.
- Проверке ролей.
- Приватным видео.
- Доступу к чужим комментариям.
- Повторному использованию токенов.

## Проверка загрузки

Проверяй не только ответ API,
но и фактическое появление объекта в хранилище.

Для тяжёлых операций используй небольшие
тестовые файлы.

## Исправление ошибок

Если тест падает:

1. Изучи traceback.
2. Найди причину ошибки.
3. Определи, где находится проблема.
4. Исправь причину, а не только симптом.
5. Добавь или обнови тест.

Не отключай тесты и не меняй ожидаемый результат
только для того, чтобы получить зелёный отчёт.

## Завершение

Запускай тесты через виртуальное окружение:

.venv/Scripts/python.exe -m pytest

В конце сообщай:
- Сколько тестов запущено.
- Сколько прошло.
- Сколько упало.
- Какие ошибки остались.
